# BUG-003 동전 단위 정산 시 잔돈이 단위 금액보다 크게 남음

## 상태

OPEN

## 우선순위

High

## 대상 모듈

정산 기능은 다음 두 파일로 구성되어 있다.

- `sample-project/src/expense/settlement.py` — 동전 단위 정산 진입점
- `sample-project/src/expense/allocation.py` — 정산이 사용하는 단위 개수 분배 기능

증상은 `settle_by_unit` 호출에서 관측되지만, 원인이 두 파일 중 어디에 있는지는 Planner가 실제 코드를 확인해 판단한다.

## 문제 상황

`settle_by_unit(amount, people, unit)` 은 각자 낼 금액을 `unit` 단위로 청구하고, 청구하고 남은 잔돈을 함께 반환한다.

청구 단위가 `unit` 이므로 남는 잔돈은 항상 `unit` 보다 작아야 한다.
그런데 실제로는 `unit` 이상의 금액이 잔돈으로 남는다. 100원 단위 정산에서 200원이 잔돈으로 남는 식이다.

잔돈으로 빠진 금액은 아무에게도 청구되지 않으므로, 인원수가 많을수록 청구되지 않고 남는 금액이 커진다.

## 재현 절차

```python
from expense.settlement import settle_by_unit

print(settle_by_unit(1400, 4, 100))  # ([300, 300, 300, 300], 200)
print(settle_by_unit(1000, 3, 100))  # ([300, 300, 300], 100)
print(settle_by_unit(10, 3, 1))      # ([3, 3, 3], 1)
```

## 현재 동작

- `settle_by_unit(1400, 4, 100)` → `([300, 300, 300, 300], 200)`
  - 잔돈 200원. 청구 단위 100원보다 크다.
  - 400원씩 낼 수 있는 사람이 2명 있는데도 전원이 300원만 청구받았다.
- `settle_by_unit(1000, 3, 100)` → `([300, 300, 300], 100)`
  - 잔돈 100원. 청구 단위 100원 이상이다.
- `settle_by_unit(10, 3, 1)` → `([3, 3, 3], 1)`
  - 단위가 1원이면 잔돈은 항상 0원이어야 하는데 1원이 남는다.

## 기대 동작

- 남는 잔돈은 항상 `unit` 보다 작아야 한다. (`0 <= change < unit`)
- 각 사람의 청구액은 항상 `unit` 의 배수여야 한다.
- 청구액 합계와 잔돈의 합은 항상 입력 금액과 같아야 한다.
- 사람별 청구액 차이는 최대 `unit` 1개여야 한다.
- 남는 단위는 일정한 기준으로 배분되어야 한다.
- `unit` 이 1원이면 결과는 단순 분배와 같아야 한다.
- 기존 입력값 검증 동작은 유지되어야 한다.
  - `people <= 0` 이면 `ValueError`
  - `unit <= 0` 이면 `ValueError`
  - `amount < 0` 이면 `ValueError`
- `split_amount`, `split_by_weights`, `format_split` 의 동작에는 영향을 주지 않아야 한다.

## 영향 범위

- `unit` 단위로 나누어떨어지지 않는 모든 정산
- 청구되지 않고 남는 금액은 최대 `unit * (people - 1)` 원까지 커진다
