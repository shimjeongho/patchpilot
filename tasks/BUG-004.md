# BUG-004 정산 대조 시 이체되지 않고 남는 금액 발생

## 상태

OPEN

## 우선순위

High

## 대상 모듈

`sample-project/src/expense/reconciliation.py`

## 문제 상황

`reconcile_payments(paid)` 는 각자 이미 낸 금액 목록을 받아, 정산을 맞추기 위해 누가 누구에게 얼마를 보내야 하는지를
`(보내는 사람, 받는 사람, 금액)` 이체 목록으로 반환한다. 사람은 입력 리스트의 인덱스로 식별한다.

이체 목록을 모두 반영하면 전원의 부담액이 공평해져야 한다.
그런데 실제로는 이체되지 않고 남는 금액이 생겨서, 정산이 끝난 뒤에도 누군가는 여전히 더 내고 누군가는 덜 낸 상태로 남는다.

덜 낸 사람이 여러 명이거나 더 낸 사람이 여러 명일 때 증상이 두드러진다.

## 재현 절차

```python
from expense.reconciliation import reconcile_payments

print(reconcile_payments([9000, 0, 0]))        # [(1, 0, 3000)]
print(reconcile_payments([4000, 2000, 0, 0]))  # [(2, 0, 1500), (3, 1, 500)]
```

## 현재 동작

- `reconcile_payments([9000, 0, 0])` → `[(1, 0, 3000)]`
  - 3,000원만 이체된다. 실제로 옮겨야 할 금액은 6,000원이다.
  - 이체를 반영한 최종 부담액: `[6000, 3000, 0]`
  - 0번은 여전히 6,000원을 부담하고 2번은 한 푼도 부담하지 않는다.

- `reconcile_payments([4000, 2000, 0, 0])` → `[(2, 0, 1500), (3, 1, 500)]`
  - 2,000원만 이체된다. 실제로 옮겨야 할 금액은 3,000원이다.
  - 이체를 반영한 최종 부담액: `[2500, 1500, 1500, 500]`
  - 0번은 2,500원을 부담하고 3번은 500원만 부담한다.

- `reconcile_payments([1000, 1000, 1000])` → `[]`
  - 전원이 같은 금액을 낸 경우에는 이체가 발생하지 않는다. 이 동작은 정상이다.

## 기대 동작

- 이체 목록을 모두 반영하면 전원의 최종 부담액 차이는 최대 1원이어야 한다.
- 이체 전후로 전체 금액의 합계는 변하지 않아야 한다.
- 각 이체 금액은 1원 이상이어야 한다. 금액이 0인 이체는 목록에 넣지 않는다.
- 이체 건수는 인원수보다 적어야 한다. (`len(transfers) <= len(paid) - 1`)
- 나누어떨어지지 않아 생기는 1원 단위 차이는 일정한 기준으로 배분되어야 한다.
- 전원이 같은 금액을 낸 경우와 인원이 1명인 경우에는 빈 목록을 반환해야 한다.
- 기존 입력값 검증 동작은 유지되어야 한다.
  - `paid` 가 비어 있으면 `ValueError`
  - 음수 금액이 있으면 `ValueError`
- `split_amount`, `split_by_weights`, `settle_by_unit`, `format_split` 의 동작에는 영향을 주지 않아야 한다.

## 영향 범위

- 덜 낸 사람과 더 낸 사람의 금액이 정확히 일치하지 않는 모든 정산
- 참여 인원이 많을수록 이체되지 않고 남는 금액이 커진다
