# BUG-002 가중치 분배 시 나머지 금액 유실

## 상태

OPEN

## 우선순위

High

## 대상 모듈

`sample-project/src/expense/weighted_splitter.py`

## 문제 상황

정산 금액을 사람별 가중치 비율에 따라 나눌 때, 나누어떨어지지 않는 금액에서 나머지가 유실된다.

10,000원을 가중치 `[1, 2, 4]` 로 분배하는 것과 동일한 구조에서, 각 사람의 몫이 모두 내림 처리되어
분배된 금액의 합계가 원래 금액보다 작아진다.

가중치 분배는 대부분의 입력에서 나누어떨어지지 않으므로, 이 유실은 예외 상황이 아니라 기본 동작에서 발생한다.

## 재현 절차

```python
from expense.weighted_splitter import split_by_weights

result = split_by_weights(10, [1, 2, 4])
print(result)       # [1, 2, 5]
print(sum(result))  # 8

result = split_by_weights(11, [0, 1, 2])
print(result)       # [0, 3, 7]
print(sum(result))  # 10
```

## 현재 동작

- `split_by_weights(10, [1, 2, 4])` → `[1, 2, 5]`
- 분배 금액의 합계: 8원 / 입력 금액과의 차이: 2원 부족
- `split_by_weights(11, [0, 1, 2])` → `[0, 3, 7]`
- 분배 금액의 합계: 10원 / 입력 금액과의 차이: 1원 부족

## 기대 동작

- 분배 금액의 총합은 항상 입력 금액과 같아야 한다.
- 각 사람의 몫은 자신의 이상적인 몫(`amount * weight // total_weight`)보다 1원을 초과해 많이 받지 않아야 한다.
- 나머지 금액은 일정한 기준으로 배분되어야 한다.
- 가중치가 `0` 인 사람은 어떤 경우에도 금액을 받지 않아야 한다.
- 기존 입력값 검증 동작은 유지되어야 한다.
  - `weights` 가 비어 있으면 `ValueError`
  - 음수 가중치가 있으면 `ValueError`
  - 총 가중치가 `0` 이면 `ValueError`
  - `amount < 0` 이면 `ValueError`
- `split_amount` 와 `format_split` 의 동작에는 영향을 주지 않아야 한다.

## 영향 범위

- 가중치가 균등하지 않은 모든 정산
- 유실 금액은 최대 `len(weights) - 1` 원까지 커진다
