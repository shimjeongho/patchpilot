## 수정 가설
`split_tip` 의 금액 유실은 **내림(`//`)이 두 번 발생하고, 두 번 모두 버려진 나머지를 아무도 부담하지 않기 때문**이라고 본다.

- `bill_share = bill // people` 에서 `bill % people` 이 유실된다.
- `tip_share = bill_share * tip_percent // 100` 은 팁 기준이 청구 금액 전체가 아니라 이미 내림된 1인당 금액이라, 요구 팁(`bill * tip_percent // 100`)보다 작은 값이 청구된다.
- `[bill_share + tip_share] * people` 은 동일 값 복제이므로 합계가 항상 `people` 의 배수가 되어, 구조적으로 1원 단위 잔여분을 배분할 수단이 없다.

따라서 **팁 기준을 `bill` 전체로 바꿔 총액을 먼저 확정하고, 그 총액 하나를 앞 사람부터 나머지를 배분하는 방식으로 나누면** 합계 보존·길이 보존·공평성·배분 순서 요구사항이 동시에 충족된다고 판단했다.

## 변경 파일
- `sample-project/src/expense/tip.py`

## 변경 이유
`plan.md §5` 의 두 원인(청구 금액 분배 시 나머지 유실, 팁 계산 기준 오류로 인한 추가 유실)을 제거하고, `plan.md §3` 의 불변식(합계 보존, 길이 보존, 최대 1원 차이, 앞 사람 우선 배분)을 만족시키기 위해 `split_tip` 의 계산 순서와 배분 방식을 수정했다.

- `split_tip(10000, 3, 10)`: 팁 `10000 * 10 // 100 == 1000` → 총액 11000 → `[3667, 3667, 3666]`
- `split_tip(10000, 3, 0)`: 팁 0 → 총액 10000 → `[3334, 3333, 3333]`
- `split_tip(9, 3, 10)`: 팁 `9 * 10 // 100 == 0` → 총액 9 (1원 미만 팁은 청구하지 않음)

## 구현 방법
1. **팁 계산 기준 변경 (`plan.md §8-1`)**
   `tip = bill * tip_percent // 100` 으로, 청구 금액 전체에 팁률을 적용해 한 번만 내림한다. 내림이므로 1원 미만 팁은 자연히 청구되지 않는다.

2. **총액 확정 후 배분으로 순서 변경 (`plan.md §8-2`)**
   `bill + tip` 로 총액을 먼저 만들고, 그 총액 하나만 인원수로 나눈다. 내림 발생 지점이 팁 계산 1회로 줄어든다.

3. **공용 배분 함수 재사용 (`plan.md §8-3`)**
   `[x] * people` 복제 대신 `expense.splitter.split_amount(bill + tip, people)` 를 사용했다. 중복 구현을 새로 만들지 않고 재사용을 택한 근거는 다음과 같다.
   - `splitter.py:21-28` 이 이미 "몫 계산 후 나머지를 앞 사람부터 1원씩 배분" 하는, 이번 요구사항과 **완전히 동일한 규칙**을 구현하고 있다.
   - `settlement.py:3,28` 이 `expense.allocation.allocate_units` 를 import해 쓰는 것처럼, 이 프로젝트는 배분 규칙을 모듈마다 중복 구현하지 않고 공용 함수를 재사용하는 스타일이다.
   - `splitter.py` 는 외부 import가 없어 `tip.py` → `splitter.py` 방향의 단방향 의존만 생기고 순환 import 위험이 없다.
   - 인자 계약 확인: `split_amount(amount, people)` 는 `people <= 0`, `amount < 0` 일 때 `ValueError` 를 던진다. `tip.py` 자체 검증이 먼저 수행되어 `people >= 1`, `bill >= 0`, `tip_percent >= 0` 이 보장되므로 `bill + tip >= 0` 이 항상 성립한다. 즉 정상 경로에서 `split_amount` 의 검증에 걸려 `amount` 기준 예외 메시지가 노출되는 일은 없다.

4. **기존 검증 블록 유지 (`plan.md §8-4`)**
   `people` → `bill` → `tip_percent` 순서의 `ValueError` 검증 3개는 문구·순서 모두 그대로 두었다. 특히 `tip_percent < 0` 검증이 총액 계산보다 앞에 있어야 음수 팁률로 총액이 청구 금액보다 작아지는 결과를 막을 수 있다.

5. **주석/Docstring 정리 (`plan.md §8-5`)**
   기존 Docstring은 "팁은 청구 금액에 tip_percent를 적용해 계산" 이라고 이미 수정 후 동작을 정확히 기술하고 있어(오히려 기존 구현이 Docstring을 어기고 있었음) 다시 쓰지 않았다. 대신 코드만 보고 알기 어려운 두 가지 의도만 주석으로 남겼다.
   - 팁을 왜 1인당 금액이 아닌 청구 금액 전체 기준으로 계산해야 하는지
   - 왜 총액을 먼저 확정한 뒤 한 번만 배분하는지, 그리고 `split_amount` 를 재사용한 근거

변경 후 함수 본문은 검증 블록을 제외하면 3줄이며, 시그니처·반환 타입·예외 계약은 모두 그대로다.

## 예상 부작용
- **총액 자체의 변화(의도된 변경)**: 팁 기준이 `bill // people` 에서 `bill` 전체로 바뀌므로, 총액이 인원수로 나누어떨어지지 않던 입력에서 청구 총액이 기존보다 커진다. 이는 `plan.md §1` 이 명시한 요구 동작이다. `expense` 패키지 내 다른 모듈은 `tip.py` 를 import하지 않으므로 영향 범위는 `split_tip` 호출자에 한정된다.
- **신규 모듈 의존 추가**: `tip.py` 가 `expense.splitter` 에 의존하게 된다. 외부 라이브러리 의존은 아니며(`CLAUDE.md §24` 위반 없음), 단방향이라 순환 import는 발생하지 않는다. 다만 이후 `split_amount` 의 배분 규칙이 바뀌면 `split_tip` 도 함께 영향을 받는다.
- **경계값**: `bill == 0` → 총액 0 → `[0, 0, 0]`, `people == 1` → `[bill + tip]`, 총액 < `people` (예: `split_tip(9, 3, 10)`) → `[3, 3, 3]` 로 몫 0 이상이 보장되고 길이도 `people` 로 유지된다. 음수 몫이나 길이 불일치는 발생하지 않는다.
- `splitter.py`, `allocation.py`, `settlement.py` 등 다른 모듈은 손대지 않았으므로 해당 테스트에 대한 회귀 요인은 없다고 본다. 실제 통과 여부 판정은 Tester의 권한이다. (`CLAUDE.md §11`)
